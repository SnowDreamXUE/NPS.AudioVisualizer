Layout decision

左右声道频谱：三种落地路径

目标是切换到新样式后，左声道固定在岛左侧、右声道固定在岛右侧，不再受宿主插件排序影响。点击卡片可标记你倾向的方案。

A

拆成两个普通组件

继续走 IWidget 与宿主排序

宿主分配区域
← 左声道
右声道 →
插件频谱 L插件频谱 R可能被挪动
改动最少无法保证两端
  • 两个组件仍会作为插件内容参与布局。
  • 插件顺序变化时，左右频谱可能一起移动或被其他内容插入。
B

使用辅助组件层

复用 ISecondaryWidget，绕开普通排序

宿主普通内容
← 固定左端
固定右端 →
普通排序辅助层独立位置
符合需求需核实宿主坐标
  • 插件注册左右两个辅助绘制单元，不占普通排序位置。
  • 若宿主把辅助组件绘制到固定边缘，只需插件侧实现。
C

宿主增加边缘插槽

为插件提供明确的左右端覆盖层 API

宿主普通内容
← EdgeLeft
EdgeRight →
排序无关坐标明确冲突可控
最稳妥需要宿主改动
  • 宿主明确提供左右边缘绘制回调或插槽，插件只提交声道数据。
  • 可统一处理岛宽变化、媒体占位、遮挡和点击区域。

当前建议

先核对宿主 ISecondaryWidget 的实际绘制位置。如果它已经绕过 ContentOrder 且能获得边缘矩形，优先采用 B；如果只能注册但不能控制矩形，则采用 C，补充最小的宿主边缘层能力。A 不符合“忽略宿主排序”的核心要求。

验证顺序

宿主源码核对→B 可行？→插件实现
B 不可行→C：宿主边缘 API
